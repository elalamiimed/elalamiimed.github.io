01 — Research

Research interests

I want to work on AI safety: how agentic systems are evaluated, and how their behaviour is supervised when it depends on memory, tools and long context.

My background is empirical and systems-heavy. I have built LLM agents that persist memory across sessions (Amnesia, LearnyBrain) and a generation pipeline whose output is gated by a deterministic rejection checklist (Agentica). In parallel I have run quantitative research at a scale that forced methodological honesty: 41,470 labelled samples in CryptoBot, a classifier evaluated across held-out launch windows, a 20-engine macro research system, and a backtester with explicit risk constraints.

That work gave me the habits I would bring to a research group: construct datasets carefully, measure rather than assume, write down what failed, and build the infrastructure that makes an experiment reproducible. I have no peer-reviewed publications yet — my research output so far is code, datasets and written reports (18 reports in CryptoBot, internal design and evaluation notes in MISO).

I would like to start by contributing to evaluation infrastructure and well-scoped empirical studies — particularly agent memory, tool use, and failure modes that only appear over long horizons — and grow into independent research under supervision.

02 — Selected work

Projects

P01

Agent systems

private

LearnyBrain — adaptive tutoring agent

An agent harness for learning. Given a goal, it probes where a learner's understanding ends, maps the dependency path to that goal, then teaches one reasoning step at a time — checking and repairing each step instead of producing a single answer.

A persistent knowledge graph carries state across sessions and feeds later lessons. It was built as an exercise in agent state, step-wise verification and long-horizon coherence — the properties I would want to measure in a safety evaluation.

Methods
Probing, dependency mapping, step-wise verification, persistent state
Stack
TypeScript · Next.js · Electron

P02

LLM memory infrastructure

public

Amnesia — local-first memory for LLM agents

A long-term memory layer for Ollama models: hybrid SQLite full-text and embedding recall behind an MCP interface, so an agent can remember who it is talking to and what has already been done. No cloud, no telemetry.

The design question that interests me is the audit surface — what an agent stores, when it retrieves it, and how stale or contradictory memories change behaviour.

Methods
Hybrid retrieval (full-text + embeddings), MCP tool interface, local persistence
Stack
Python · SQLite · MIT licensed
Scale
~11.5k lines · 16 test files

Repository

P03

Constrained generation

public

Agentica — guarded bilingual writing pipeline

A bilingual (EN/中文) article pipeline: a 27-question intake form produces a publication-ready draft, which is then checked against a deterministic rejection checklist distilled from 17 approved articles and 130 headings.

Every draft is audited before submission — the checklist is code, not judgement. It is the closest thing I have built to a guardrail with testable criteria, and it taught me where explicit specifications help and where they merely relocate the failure.

Methods
Structured intake, style fingerprinting, deterministic checks, QA test suite
Stack
Python · LLM APIs
Scale
13 QA test files · 0 Chinese-only headings across 130 checked

Repository

P04

Empirical study

public

CryptoBot — 41,470 launches, measured

An empirical study of newly launched Solana tokens: 41,470 labelled launches and 45,000+ on-chain tapes, used to test whether early observables predict extreme outcomes.

A gradient-boosted classifier improved from ROC-AUC 0.60 to 0.75 as more launch-window data became available — a useful reminder that the metric, not the model, is the interesting object. Paper trading only: no wallet, no signing.

Methods
Dataset construction, labelling, class imbalance, held-out evaluation, written reporting
Stack
Python · pandas · scikit-learn · XGBoost
Scale
18 written reports · 598 of 1,370 tokens reached ≥1000×

Repository

P05

Research system

private

MISO — 20-engine gold macro research system

A research system for XAUUSD: twenty signal engines — COT positioning, intermarket, volatility, ETF flows, COMEX and USD-liquidity among them — aggregate into weekly and daily long/short decisions, with an 18-tab dashboard and backtests.

The engineering problem is provenance: every signal must be traceable to its input, and every decision reproducible from stored state.

Methods
Signal aggregation, reproducible backtests, provenance and test coverage
Stack
Python · FastAPI · SQLite · Streamlit · TypeScript
Scale
82k lines · 486 files · 37 test files

P06

Systems engineering

local only

Pump Terminal — fail-closed trading terminal

A production-oriented Solana trading terminal: realtime candles and tape, volume profile, a deterministic paper-trading replay, and a three-gate risk engine. The live gate fails closed — if any precondition cannot be verified, the system does nothing.

It is not an AI-safety project, but it is the closest engineering analogue I have to enforcing hard constraints in a system that must never act on an unverified assumption.

Stack
FastAPI · Next.js · React · Postgres/TimescaleDB · Redis · Docker
Scale
116k lines · 552 Python tests · 25 TypeScript tests · 6 end-to-end specs

P07

Evaluation methodology

public

Session-Sweep Engine — strategy as an evaluable spec

A modular, event-driven backtester for an XAUUSD session-liquidity-sweep strategy: 1-minute sweep detection, candlestick confirmation, ATR-based stops and OCO brackets, run on real gold data.

Every rule from the playbook became an explicit, testable precondition — seven gates, a 2% risk model and a daily circuit breaker — an exercise in turning a vague idea into an evaluable specification.

Stack
Python · Backtrader · Pydantic
